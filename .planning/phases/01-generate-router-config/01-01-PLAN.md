<objective>
Deliver a standalone host-run generator script, `gen-router-config.sh`, that reads the
same Web-of-Trust relay list `stream-relays.sh` already parses (`relay_urls:` in
`~/deepfry/web-of-trust.yaml`) and emits a streams-only `strfry router` config
(`~/deepfry/strfry-router.config`) with `pluginDown = "/app/plugins/bloom"` baked into the
single ingest stream. This is config-authoring only — wiring the `ROUTER=` entrypoint
(Phase 2) and live verification (Phase 3) are out of scope (per D-01, CONTEXT phase boundary).

Purpose: Establish the single-source-of-truth config artifact that Phase 2 will bind-mount
and load. The relay list stays owned by the WoT list (CFG-01); the whitelist gate is
baked into every ingestion path config-side (ING-02, D-13) so no router-down event can
bypass the bloom filter.

Output: `gen-router-config.sh` (new, repo root) and `test/gen-router-config.bats`
(automated shape assertions). At runtime the script emits `~/deepfry/strfry-router.config`
which Phase 2 bind-mounts to container `/app/strfry-router.config`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WoT relay list → generated config | The `relay_urls:` list drives which upstream relays the router connects to. A poisoned/empty list changes the ingest set. |
| generated config → router-down ingestion | Every event downloaded from an upstream relay crosses into the canonical LMDB. `pluginDown` is the ONLY gate on this path (global writePolicy does not apply). |
| generator → `~/deepfry/` config dir | The script runs on the host with write access to the protected config dir. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | emitted `streams.ingest` stream | mitigate | `pluginDown = "/app/plugins/bloom"` is MANDATORY on the stream (D-13). Omitting it silently bypasses the whitelist — the global writePolicy does NOT gate router-down events (RESEARCH.md, source-verified). Task 2 acceptance asserts exactly one `pluginDown` bloom line exists; absence fails the plan. Release blocker (ING-02). |
| T-01-02 | Tampering | WoT `relay_urls:` list (empty/poisoned) | mitigate | On empty list, run WoT discovery then re-read (D-05); if still empty, FAIL HARD — exit non-zero, emit NO config (D-06). Never substitute a hardcoded fallback set — a stale/wrong ingest set is worse than none. The WoT list stays the single source of truth (CFG-01). Task 1+2 assert fail-hard-on-empty with no config written. |
| T-01-03 | Denial of Service | golpe silently drops `streams{}` if placed in the global `--config` | mitigate | Emit a STANDALONE file whose only top-level key is `streams` with NO `db`/`relay` (D-10). Mixing `streams` into the global config is the documented zero-streams failure. Task 2 asserts no top-level db/relay key present. |
| T-01-04 | Tampering | generator writing into protected `~/deepfry/` | accept | Script writes ONLY its own `$ROUTER_CONFIG` (D-09) and never seeds/edits `web-of-trust.yaml` (the discovery tool manages that file itself). CLAUDE.md config-dir rule. Test asserts sibling files untouched. |
| T-01-05 | Information Disclosure | relay URLs in generated config | accept | Relay URLs are public nostr endpoints; no secrets are written to the config. No mitigation required. |
| T-01-SC | Tampering | package/toolchain installs | accept | No npm/pip/cargo installs in this phase. Discovery invokes an existing in-repo Go tool (`go run` via `make`) — no new third-party package introduced by this phase. |
</threat_model>
