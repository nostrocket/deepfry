## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem → strfry container | The router config is bind-mounted from the host `~/deepfry/` config dir; the container reads it read-only. |
| router streams → strfry | Once wired, the router will connect OUT to attacker-influenced WoT relay URLs and ingest events. In this phase the path is only wired + config-load-proven; live event gating (bloom pluginDown) is Phase 3's proof — but the config already carries per-stream pluginDown from Phase 1. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering | Router mount duplicating/overriding db path | mitigate | Router mount is streams-only (Phase 1 D-10); no db env/line added — db resolves solely from /etc/strfry.conf. Verify negative: no db added to the router mount. |
| T-02-04 | Elevation of Privilege | Ingested router-down events bypassing the whitelist | mitigate (config-side) | Per-stream pluginDown=/app/plugins/bloom is baked into the Phase 1 config the mount points at; the global writePolicy does NOT gate router-down events. Live proof that gating actually fires is Phase 3 (ING-02 verification), not this wiring phase. |
