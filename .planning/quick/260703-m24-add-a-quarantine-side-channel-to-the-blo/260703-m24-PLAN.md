<objective>
Give the `bloom` writePolicy plugin the same quarantine side-channel the `router`
plugin already has: when the local bloom filter rejects an event (not-in-set →
not whitelisted), forward that event fire-and-forget to the quarantine relay IF
it passes the kind-0/1/3 heuristics gate. The mainline reject decision and the
bloom filter's zero-per-event-HTTP property are unchanged.

Approach: reuse the proven, checker-agnostic `RouterHandler` + `RouterIOAdapter`
(the RouterHandler takes any `handler.Checker`, and the bloom plugin's
`BloomChecker` already satisfies that interface) together with the existing
`quarantine.Publisher` and `heuristics.Filter`. The bloom-specific pieces
(`BloomChecker` + `BloomFetcher` cold-start / disk-persist / ticker) stay intact.
NO new machinery: the kind allowlist (heuristics) and the publisher are reused,
not reimplemented.

Purpose: the active StrFry plugin (config/strfry/strfry.conf:140 → `/app/plugins/bloom`)
currently drops rejected events silently; this makes it feed the quarantine relay
for parallel-WoT analysis, matching the router.
Output: modified bloom config + entrypoint, config test coverage, README docs.
</objective>
